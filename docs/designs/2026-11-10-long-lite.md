# Long-lite: lighter long pipeline that passes on the first run (2026-11-10)

Laptop Linux (kamil-jan). Scope: longs only (Kamil 2026-11-10). Shorts, posts, carousels and blog are out of scope for now.

## Problem (evidence)
- Film 2026-11-04: 62 .py modules, 16 tools called in `run_v4.sh`, 99 checklist items (49 long, 33 short, 17 out), 202 commits since 11-01.
- NOTES_LOG rows 31-38 (the v5 render) by cause:
  - Real defects in the film, caught by a gate: 35 (last window lost 20 s), 36 (audio packet / lips), 38 (music under soft words).
  - Process, not the film: 31 (code changed after approval -> everything stale), 32 (load from another process), 33 (no watchdog), 34 (only the long was checked before render), 37 (a new gate crashed on the long's plan after 50 min).
- Conclusion: the checks themselves aren't the problem; they found real defects. The problem is that they ran only after a 50-60 min render, and that the code was changing during the film.

## External repos (already surveyed 2026-11-05, `style/REF-oss-survey.md`)

- claude-youtube-editor (MIT): `snap_tail` + `entry_check` (cut edges). Already in the backlog as item 5 (`REF-oss-survey.md:371`). It also has a cut-editor UI = the same need Kamil has ("ucinasz za dużo").
- OpenChatCut AGPL, auto-editor: evaluated earlier; neither changes the problem above.
- Switching to someone else's system = losing the 99 rules Kamil already set. Not worth it.

## Change (4 steps, longs only)
1. **Code freeze per film.** `manifest.py` stamps the commit at the film's start; run_v4 refuses to start the final render if the commit changed since the dry run. Fixes found during the film go to `NOTES_LOG` as "next film".
2. **Dry run on a proxy (the "first time" mechanism).** `run_v4.sh DRY=1` = `assemble.py --proxy` (640 px, ultrafast; already exists, `assemble.py:29-36`) + ALL post checks (words cut/sound, sync, av, lip, film_check). The sound is identical to the final render, so the sound checks give the same verdict in about 1/5 of the time. The final render starts only after the dry run passes, on the same commit.
3. **Kamil's cut review in Kdenlive as a stage.** build_edl -> project `.kdenlive` (generator `edl2mlt.py` moves to the repo, NOT_FILM) -> Kamil drags cut edges (ripple) -> `kden_import.py` reads the timeline back into the plan's keeps -> dry run -> render. Zero tokens spent on cuts.
4. **Blocking vs report.** Of the 49 `long.*` items: blocking = only those that caught a real defect or are cheap (<10 s). The rest = a report after the render, without stopping it. Classification = one table in `style/checklist.json` (`block: true/false`), no logic deleted.

## Production-time target (Kamil 2026-11-10: "praca przez tyle godzin nad kazdym longiem to jest zbyt duzy koszt")

- Hours went into rebuilding the system during the film, not into editing. After the freeze, a long = data (plan, cuts, cards) on stable code.
- Metric: hours of a session per long + number of renders per long (target: 1 dry + 1 final). Logged in NOTES_LOG after each film.

## Addition: cut edges from the repos (REF-oss-survey top 10, item 5; NOT done before 2026-11-10)
- Problem "ucinasz za dużo": `build_edl.py:31` uses fixed PRE 0.10 / POST 0.16 s for every word.
- claude-youtube-editor `snap_tail` (`cutlib.py:77-90`): the word's tail is extended in 20 ms steps until the RMS drops to the floor +5 dB. `entry_check` (`analyze_cut.py:39-51`): the RMS just before the start of a piece >15 dB above the floor = a clipped start -> blocking in the dry run.
- Kamil 2026-11-10: the automatic cuts can stay as a draft; what's needed is the ability to drag a cut edge to recover a piece (step 3).

## Additions from the 2026-11-10 talk with Kamil
- Scope: long + its upload package (A/B thumbnails, YT description, chapters, srt). Shorts, posts, carousels, blog = later, on the same rules.
- No selectivity: a gate set to `=off` -> `film_check` = film not ready without `waivers` in the plan signed by Kamil; final render only after a green dry run on the same commit + plan checksum; every skipped gate is in the first line of the report.
- `long.effect_spread`: every effect kind (behind the head, underlines, side screens, keywords, screens, memes) in every third of the film (<=3 uses: 2 of 3 thirds).
- Tokens: a watchdog wakes the session only on DONE/FAILED/STALL; gates print a one-line verdict; stills reviewed only when flagged by scene_check.
- Measurement: `timeline.log` = timestamp per stage + `get_usage` at the start and end of the film. Targets: ~4-6 h RAW -> mp4 (from the 2nd film after the changes), ~5-10 % of the weekly limit per long.
